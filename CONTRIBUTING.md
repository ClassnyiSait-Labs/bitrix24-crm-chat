# Как внести вклад

Спасибо за интерес к проекту. Issues и pull requests приветствуются.

## Сообщить о баге

Заведите [issue](https://github.com/ClassnyiSait-Labs/bitrix24-crm-chat/issues) и укажите:

- версию Bitrix24 и версию PHP;
- версию модуля (`classnyisait.crmchat/install/version.php`);
- что делали, что ожидали увидеть и что увидели.

Без версии платформы и PHP разобраться в отчёте почти невозможно — на разных
сборках поведение отличается.

## Уязвимости

Не заводите публичный issue. Порядок описан в [SECURITY.md](SECURITY.md).

## Локальная разработка

Модуль ставится копированием папки `classnyisait.crmchat` в `/local/modules/`
(или `/bitrix/modules/`) и установкой через **Marketplace → Установленные решения**.

### PHP-тесты

```bash
composer install
composer test
```

Тесты покрывают только чистую логику — ту, что работает без ядра Битрикса.

Всё, что обращается к базе, корзине или интерфейсу, требует живого портала и
проверяется руками: юнит-тестами такое покрыть нельзя, а имитация ядра проверяла бы
заглушку вместо модуля.

Тесты лежат в `classnyisait.crmchat/test/`.

## Стиль кода

- Отступ 4 пробела, кодировка UTF-8 без BOM, перевод строки LF.
- Именование как в существующем коде: классы `PascalCase`, методы `camelCase`,
  константы `UPPER_SNAKE_CASE`.
- Пользовательские строки — только через языковые файлы `lang/ru/`, `lang/en/`,
  никаких зашитых в код надписей.
- Любые данные из админки или от пользователя экранируются перед выводом в HTML
  и приводятся к типу перед подстановкой в SQL.

## Pull request

1. Ветка от `main`.
2. `composer test` проходит локально.
3. Один PR — одно изменение; в описании укажите, на каких версиях проверяли.
4. Изменения, заметные пользователю, добавьте в `CHANGELOG.md`.

CI прогоняет линт и тесты на PHP 8.1, 8.2, 8.3 — PR с красным CI не вливается.
